# MarkColorDemo 项目全局导航与开发指南

本文按 2026-10-20 的源码入口整理。当前 Native ABI 为 3，标准 JSON 写出格式为 3，读取兼容 v1/v2。文档描述已实现行为；设备标准板校准、光源漂移补偿尚未实现。

## 1. 新同事的阅读顺序

1. [README](../README.md)：运行目标、操作方式和测量边界。
2. 本文第 2～4 节：准备环境并沿真实处理链设断点。
3. [维护与交接检查表](维护与交接检查表.md)：确认编号、单位、资源和失败路径。
4. [代码规范](代码规范.md)：按现有规则修改，并选对应验证。

仓库根目录指包含 [MarkColorDemo.sln](../MarkColorDemo.sln) 的目录。命令都在此执行，不依赖某台电脑的固定盘符。`MainWindow.Settings.cs` 等是同一个 `MainWindow` 分部类的文件，不是独立类型。

## 2. 环境、生成和复制

| 入口 | 用途与约束 |

| [Native.Common.props](../build-support/Native.Common.props) | 原生测试项目共用编译设置；主 DLL 工程显式列出自己的选项 |

编译器由工程选择；OpenCV 的 `vc15` 是 SDK 文件夹名称，不能据此推断主项目编译器版本。改变 SDK 地址应同时检查版本和 Debug/Release 库是否齐全。`build.ps1 -OpenCvDir ...` 只覆盖本次脚本运行，VS 后续 F5 仍使用属性表。

```powershell
.\setup.ps1 -Mode Check
.\build.ps1 -Configuration Debug -NoPublish
.\build.ps1 -Configuration Release
```

普通 `dotnet build` 不能替代本解决方案需要的完整 C++ 工具链。`build.ps1` 构建四个项目，但只自动执行原生测试；托管集成验证需另行运行。

| 产物 | 路径 |
|---|---|
| Native DLL/PDB/LIB | `build/msbuild/native/<Configuration>/` |
| WPF F5 程序及依赖 | `src/MarkColorDemo/bin/<Configuration>/net10.0-windows/` |
| 原生验证程序 | `build/msbuild/tests/<Configuration>/native_tests.exe` |
| 托管验证程序 | `build/verification/<Configuration>/Verification.exe` |
| Release 发布程序 | `publish/` |
| Debug 发布程序 | `publish/Debug/` |
| 便携交付包 | `dist/MarkColorDemo-portable-<时间戳>/` |

`MarkColorDemo.dll` 是 C# 程序集，算法库是 `MarkColorNative.dll`。`run.cmd` 启动已有发布版本；它不自动编译最新源码。

## 3. 从一次操作跟踪到算法

### 单图检测

```text
MainWindow.Execute                    UI 串行化、禁用操作、统一失败展示
  → LoadCurrent
    → Task.Run → DetectionPipeline.Run
      → Native.Analyze
        → mc_analyze → analyzeImage
          → 读图 / detectionRegion
          → findCandidateContours + appendEdgeCandidates
          → 粗筛选 / 去重 / refineContour
          → measureMark + measureQuality
          → 同步排序 marks / qualities / contours
        → 复制结果与可选预览 → 释放 SafeHandle
      → Inspection.Run（存在标准时）
        → Native.Compare → mc_compare_weighted → compareMarks
        → MeasurementDecision.Color + QualitySettings.Assess
    → UI 提交 current / inspection → Refresh
      → ResultRow / ImageViewport（只展示，不重算）
```

### 单图与多图建标

`BuildStandardAsync → StandardBuilder.BuildWithRecoveryAsync → Build`。对每张图进行提取、几何对应和质量检查，全部通过后，按首张标准的点序对每次拍摄等权平均。首张图的几何用于匹配，平均颜色用于判定，跨拍摄标准差用于观察重复性。

建标失败携带 `StandardBuildException`：`AdjustStandardSourceAsync` 使用失败图打开 ROI 草稿，调整后重新检查全部采样。取消不提交；多图的 `ReviewStandard` 确认后才替换当前标准。该复核不自动扩大阈值。

`StandardProfile.From` 是从快照创建草稿的较低层入口，不执行建标质量检查；演示/测试的 `LoadPairAsync` 使用此入口。正式按钮流程走 `StandardBuilder`。

### 设置应用

`SettingsWindow` 复制参数和标准点，`ReadDraft` 统一解析输入；预览只生成临时分析。主窗口 `ApplySettingsAsync` 用 `SameExtraction` 判断是否重取色：

- 改 ROI、分割、半径或内圈：核对全部采样哈希，重建标准，并重新提取待测图。
- 改颜色因子、标签、目标或比较阈值：复用测量快照，重新计算比较结果。
- 重建时迁移人工 Lab 偏移，不把旧均值覆盖到新测量上。
- 只有准备、比较和校验都成功后，才统一提交新状态。

### 批量与报告

`Batch_Click → BatchDetector.RunAsync`。生产端逐图检测，消费端生成报告，中间有界队列容量 2。用户取消在图像边界停止生产，已经完成的条目仍写入；写盘失败会解除生产端等待并传播异常。队列容量不等于整个进程只持有两张图：两端当前处理和标准预览也可能占内存。

`Export_Click → ReportExport` 复用已有结论。CSV 不要求位图；HTML 使用压缩预览及原图坐标 SVG。临时文件在成功关闭后提交，失败时不覆盖原报告，可能留下临时文件用于排查。

## 5. 进入 Native 之前要记住的契约

- 原图坐标从左上角起，x 向右、y 向下，单位 px；ROI 为整图的 0..1 比例；WPF 平移采用 DIP。
- `StandardMark.Id` 是业务编号；标准列表位置是 `referenceIndex`；`ObservedIndex` 才能访问待测图的三个并行数组。不要用编号直接索引。
- `McMark/Mark` 128 字节，`McComparison/Comparison` 80 字节，`McAlignment/Alignment` 56 字节，`McQuality/MarkQuality` 80 字节，色差参数 24 字节；x64、cdecl、Pack=8。
- `mc_analyze` 成功后交出独占句柄；`SafeHandle` 负责释放。OpenCV/STL 和 C++ 异常不能跨 DLL。
- 借用的 BGR 指针只在句柄存活时有效；复制并冻结后才可以交给 WPF。`mc_get_contour` 的容量是点数，BGR stride/length 是字节数。
- 负返回值表示接口失败；`mc_last_error` 是线程局部文本，应立即读取。部分只读访问接口的非法参数路径不刷新错误文本，不能将旧文本误认为本次错误原因。
- Native 配准状态 0/1/2 是匹配/缺失/歧义，不是业务 OK/NG；匹配成功后仍需检查质量和颜色阈值。

Lab 每通道的截尾均值、内圈像素标准差、跨拍摄样本标准差属于三种统计口径。`StandardMark.Value.L/A/B` 可以人工调整；`MeasuredLab` 保留原始采样均值。背景环亮度是测量资格证据，不是自动白平衡或漂移补偿。

## 6. 断点与常见排障

选择 Debug / x64，启动 WPF 的混合调试配置，在 `mc_analyze` 设断点，加载图像后 Native DLL 才被调用。进入 `analyzeImage` 看 ROI/候选，进入 `measureMark` 看采样掩膜，进入 `compareMarks` 看对应关系，最后看 `Inspection.CreateRow` 和 `QualitySettings.Assess`。

| 现象 | 先检查 |
|---|---|
| Native 断点空心 | VS“模块”窗口实际加载路径、配置与 PDB；不要同时看旧 publish 和新 Debug 程序 |
| OpenCV 链接或加载失败 | `OpenCV.props` 的 include/lib/bin、454 与 Debug 后缀 d、x64 一致性 |
| 轮廓存在却配准不确定 | 标准是否同版式、ROI、最大平移/旋转/比例；重复间距与缺点可能造成真实歧义 |
| 相机换分辨率后仍失败 | 半径是原图像素；等比例分辨率补偿不代表不同视野或镜像可直接复用标准 |
| 无法可靠测量 | 看质量原因和原图，不能只扩大 ΔE00 阈值 |
| 标准图预览消失 | 原图是否存在且 SHA-256 一致；保存目标仍可用于比较 |
| 清除标准后想恢复 | 重新读取已保存 JSON；清除仅复位当前会话，不删除标准文件 |
| 复制项目后图库验证失败 | 回归程序依赖特定命名与样图，不依赖项目本身的固定位置 |

```powershell
.\build-support\check-symbols.ps1 -Configuration Debug
```

符号检查证明可解析源码位置，不代替实际 GUI 断点交互。

## 7. 验证入口和数据要求

| 入口 | 输入与验证范围 |
|---|---|
| `native_tests.exe` | 无外部图库；数学参考值、合成圆点、质量、尺度、匹配和异常输入 |
| `Verification.exe <图库根目录>` | 原始回归版式；标准/恢复/质量/报告/WPF 等集成验证 |
| `Verification.exe --camera-scale <新图库> <旧图库>` | 专用两套相机数据，点数及 ROI 约定写在 `CameraScaleTests` |
| `Verification.exe <图库根目录> --pair-report` | 输出上下实拍配准的宽松/严格平移对照 |
| `Verification.exe <图库根目录> --benchmark <标签>` | 分阶段性能试验；需要相同配置、硬件、预热和输入才可比较 |
| `MarkColorDemo.exe --self-check [样图]` | 输出运行目录 `self-check.json`，检查 ABI 与实际加载模块；不做完整测色验收 |

默认集成夹具要求“优良品/2-上.bmp”“优良品/2-下.bmp”“M通道偏小二档/2-上.bmp”，以及用于其他标准的同名参考图。测试将文件名含“左/右”视为单点，其余为五点；不要对任意图库套用此规则。

若实际图库改名，可在独立验证目录建立只用于测试的副本，记录源路径和 SHA-256 映射，不修改原图或偷偷改变测试期望。`verify.ps1 -GalleryRoot` 接受夹具根目录，默认父目录仅适用于原布局。

```powershell
.\format.ps1 -Check
.\build.ps1 -Configuration Release
.\verify.ps1 -GalleryRoot 'D:\MarkColorFixtures' -Configuration Release
```

托管验证会写项目 `verification` 的报告及离屏截图；同名文件可能覆盖，应先归档旧证据。截图证明布局可渲染，不证明所有真实鼠标/多屏操作。历史实拍通过数量不等于现场误检率/漏检率。

## 8. 交给同事前

源码交付包含 Git 跟踪源码、工程、脚本和 `docs`；SDK、运行包及真实图库单独交付。JSON 引用的图像需要按哈希和相对目录恢复，不能仅凭路径同名替换内容。

便携包通过 `prepare-handoff.ps1` 生成，含文档但不含源码；文档内源码链接仅在完整源码仓库中可用。`-SkipBuild` 必须建立在确认 publish 已更新的前提下。打包和安装脚本会写文件或准备环境，不应把它们当作只读检查命令。

交接时逐项执行 [维护与交接检查表](维护与交接检查表.md)，并保留本次实际验证结果。以后更新接口、状态或文件拆分时同步更新本指南及解决方案文档条目。
