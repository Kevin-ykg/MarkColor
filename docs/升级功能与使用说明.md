# 多图标准、测量质量与便携部署

本轮版本：2026-09-24；标准 JSON schema 2；Native ABI 2。继续使用统一解决方案 `MarkColorDemo.sln`，启动项目为 MarkColorDemo，平台 x64。

## 1. 多图采样建标

1. 点击 **多图采样建标**，选择同一合格膜片、同一版式在不同位置的 2–100 张独立拍摄图像。
2. 第一张图作为几何基准；其余图先做几何配准，再按对应关系整理点位。匹配不确定、缺点、多点或质量不合格的图片会报出文件名和原因，整次建标不应用，原标准保留。
3. 在复核窗口查看每点的平均 Lab、拍摄间标准差和各次采样相对均值的最大 ΔE00，确认后应用。偏差超过当前阈值会提示检查采样波动。每次拍摄等权：`平均 L = Σ L_i / N`，a、b 同理。几何位置保留第一张，不平均不同位置的坐标。
4. 确认墨路标签和逐点阈值，点击 **保存标准**。第一张图只是显示及几何基准，检测使用多次采样平均值。

单次图像的 Lab 仍由原图“轮廓内区域 ∩ 内圈”计算，两端各去掉 5% 后求均值。多图统计针对这些单图测量值；拍摄间 σ 使用 N−1 分母，与图像内像素 σ 是两个指标。多图平均不会自动放宽 ΔE 阈值，也不能替代成像标定。

标准保存采样文件、SHA-256、逐点 Lab、配准变换、采样次数、原始均值、人工目标值、修改原因和版本。JSON 尽量采用相对图像路径，移动整个图库后仍能找到来源；只复制 JSON 仍可使用目标值检测，但原图缺失时无法预览或重提取。

## 2. 测量质量与结论

成功配准后，每个对应点先检查测量条件，再判断颜色；证据不足输出 **无法可靠测量**，不归入颜色 NG。整图只要存在无法测量点，整图即为无法可靠测量，其他点的具体结论仍保留。

| 检查 | 证据及默认值 |
|---|---|
| 过曝 | 内圈 B/G/R 同时 ≥250 的像素超过 5% |
| 严重欠曝 | 内圈 B/G/R 同时 ≤5 超过 40%，且背景环 L* <15；避免把正常黑色 mark 直接当成欠曝 |
| 疑似反光 | 内圈局部中性高亮像素覆盖超过 4% |
| 模糊 | 径向 90%→10% 边缘过渡宽中位数超过半径的 35%；低对比度单独评价 |
| 轮廓精度 | 未精修成功、BGR 边缘差 RMS <2、边缘支持比例 <55% 或综合置信指标 <0.2 |
| 采样不足 | 少于 64 像素或实际轮廓覆盖内圈不足 80% |

所有阈值在 **设置 / 测量质量** 中可调整并随标准保存。置信指标是工程评分，不是校准后的概率；反光是图像风险判断，不能仅凭 RGB 确定物理原因。过曝检查聚焦中性高亮全通道截断，不能覆盖所有单通道饱和情况。上线前必须以实际相机、材料和照明确认阈值。

统一业务枚举 `DetectionVerdict` 区分：已量化、OK、色差 NG、缺少圆点、多余圆点、匹配不确定、无法可靠测量、处理错误。界面、HTML、CSV 共用 `MeasurementDecision`；CSV 不再将匹配不确定写成 NG。

## 3. 弱对比度提取与精修

- 彩色/暗色原分辨率分割作为主分支；局部背景差补充分支分别处理微亮和微暗圆点，防止正负边缘连接。
- 粗定位后，仅在原图局部区域进行颜色差方向投影和半高分割，获得原尺寸轮廓；图像颜色不做增强或改写。
- 新增微暗分支额外检查闭合轮廓、置信指标和边缘宽度，排除图库中的模糊阴影。信号不足时允许不检出，不能保证所有近乎不可见圆点都有精确边界。
- `mark_quality.cpp` 输出边缘对比、支持比例、过渡宽、拟合残差和取色质量；`mark_detection.cpp` 负责候选流程和原图测色。
- 本次几何精修可能改变内圈位置及像素集合，因此颜色数值可能与上一版略有不同；建议正式标准用同组原图重新建立。

## 4. 界面操作

- **多图采样建标 / 单图建标 / 当前图设为标准**：统一通过质量检查；新标准先应用，保存后才持久化。
- 标准标题显示采样次数、版本、是否有未保存修改；关闭、替换、清除标准时提供保存/放弃/取消。
- 点击图上圆点或表格行会关联两侧对应点并局部放大。启用 **同步视图** 后缩放和平移联动，双击或“适应窗口”复位。
- **取色掩膜** 叠加轮廓与内圈的交集；显示经过屏幕缩放和抗锯齿，最终样本数量以原生像素统计为准。
- 表格下方展示所选点的质量证据和超限原因；质量不足使用黄色并保留文字状态。
- 设置分为常用、定位高级、质量、ROI/预览和逐点标准。ROI 页面左图拖框，右图预览草稿参数，预览不修改当前标准。
- 支持恢复默认检测参数、恢复原始采样均值。人工修改目标 Lab 须填写原因；修改提取参数会重建全部来源采样，保留人工相对偏移和标签/阈值。
- 操作失败时明确显示本次失败，以及仍保留的是上一次成功结果。

## 5. 批量与性能

`BatchDetector` 将检测与报告写入分为两个工作任务，有界队列最多等待两张图，避免整批原图常驻内存。CSV 批次只计算数值，不生成预览；HTML 批次复制同一次分析的原图作为预览，报告编码独立执行。

取消在图像边界停止生产，已入队的结果继续写完，报告记录处理数量。写盘失败停止生产并传播错误；最终文件仅在成功关闭后替换，失败的临时文件不会冒充完整报告。

质量检查和原分辨率精修增加了计算量。当前图库各轮 Release 单图中位耗时约 70–95 ms，随机器负载变化；不能把流水线并发等同于单张算法变快。原有计时继续保留。

## 6. 复制给同事

### 只运行软件

将 `dist/MarkColorDemo-portable-时间戳/` **整个目录**复制到 Windows x64 电脑，双击里面的 `run.cmd`。目录包含私有 .NET 10 Desktop/Core 运行时、VC++ Release 运行库、Native DLL 和 OpenCV DLL；不要求安装 VS 或 OpenCV SDK。

项目根目录 `run.cmd` / `quick-run.cmd` 会优先使用 `publish/runtime`。缺少运行时时，`setup.ps1 -Mode Run` 从 Microsoft 官方发布元数据下载并校验 SHA-512；必要时安装带 Microsoft 签名的 VC++ 运行库。

### 修改源码并调试

将项目目录一起复制，包括 `dependencies/opencv/build`，双击 `setup-dev.cmd`：

1. 检查项目内 OpenCV 4.5.4 SDK；缺失时从官方 GitHub 发行包下载并核对固定 SHA-256。
2. 检查 Visual Studio 2026 C++ 工具；缺失时安装 C++ 桌面和 .NET 桌面工作负载，Windows 可能要求管理员权限。
3. 检查 .NET 10 SDK，必要时准备项目内 SDK，然后构建统一解决方案。`global.json` 优先查找 `dependencies/dotnet`，复制后不必手动配置 SDK 路径。
4. 在 VS 打开 `MarkColorDemo.sln`，启动项目选 MarkColorDemo，Debug / x64，使用 C# + C++ 混合调试。

默认安装 VS Community；需要其他版本时运行 `setup.ps1 -Mode Development -VisualStudioEdition Professional` 或 `Enterprise`。公司已有受管 VS 时也可由管理员导入 `.vsconfig`。

```powershell
# 只检查，不下载或安装
.\setup.ps1 -Mode Check
# 构建与回归
.\build.ps1 -Configuration Release
.\verify.ps1 -Configuration Release
# 重新生成含私有运行时的便携目录
.\prepare-handoff.ps1
```

SDK 配置仍集中在 `build-support/OpenCV.props`，默认路径已改为项目内相对路径。运行软件使用 Release；Debug 的调试运行库面向开发机，不作为同事运行包。

自动下载安装分支按官方接口实现；当前机器已具备编译环境，未执行卸载后重装的干净系统验证。便携运行时和项目内 SDK 构建均单独验证。

| `native/src/mark_quality.cpp` | 原分辨率局部精修与原始质量证据 |
