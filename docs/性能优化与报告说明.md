# 性能优化、代码注释与可视化报告

## 代码阅读顺序

1. `native/include/mark_color.h`：单位、状态码、ABI、缓冲区所有权；新增耗时和 BGR 预览接口的使用期限。
2. `native/src/mark_color.cpp`：接口入口、错误返回与句柄释放；每个导出函数前都有用途/调用约束说明。
3. `native/src/mark_detection.cpp`：ROI 坐标、双分支分割、形态学范围、几何筛选、内圈和背景环取色、截尾统计。
4. `native/src/mark_matching.cpp`：标准→待测变换、Hungarian 代价、单点/双点假设、细化与歧义处理；说明为什么颜色不能参与匹配。
5. `native/src/color_difference.cpp`：按步骤解释色度修正、色相跨零、权重和蓝区交互项。
6. `DetectionPipeline.cs → Native.cs → ImagePreview.cs → ImageViewport.cs`：后台任务、结果复制、位图冻结与显示缓存。
7. `ReportExport.cs → VisualReportWriter.cs / ReportWriter.cs`：按用户所选格式生成图文报告或原始 CSV。

注释重点是参数单位、算法约束、失败语义、线程和内存生命周期；不是简单翻译每句代码。修改算法时应同步更新注释及对应回归。

## 性能改动

| 环节 | 改动 | 保持的约束 |
|---|---|---|
| 分割 | 只提取 HSV 的 S 通道；前景按行段扩展/合并后再做开闭运算 | 四次半径 2 运算保留 8 像素依赖边界；维持原分辨率和轮廓扫描顺序 |
| Lab | 内圈与背景环复用一次局部 Lab 转换 | 使用相同原图像素、采样掩膜、浮点 Lab 单位 |
| 截尾均值 | 两次 `nth_element` 替代全排序，预分配通道数组 | 两端各去掉 5%，中间样本集合不变；浮点加法顺序可能变化，须做数值回归 |
| 预览 | Native 保留已解码 BGR，WPF 在句柄释放前复制并冻结 | 不把原生借用指针留到绘图阶段；不重复从文件解码 |
| 结果更新 | 相同 Analysis 复用位图；阈值调整保留缩放和平移 | 新加载创建新快照，不做全局按路径缓存 |
| 线程 | 提取、比较、预览准备放入一个工作任务；报告图片编码也放到后台 | 界面提交在 UI 线程，批量仍在单图完成后响应取消 |

Native 结果自带 `DecodeMs / SegmentationMs / MeasurementMs`。状态栏展示提取/取色、匹配/结果、预览复制、界面提交；“界面提交”不包括后续异步 GPU/屏幕显示完成时间。

## 测量方法与证据

固定使用 `优良品/2-上.bmp` 与 `2-下.bmp`，2448×2048、5 点；每项预热 2 次，测量 20 次，报告中位数与 P95。无调试器附加，不把 Debug 和 Release 混在一起计算。

Release 本机中位数（毫秒）：

| 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 单图 Native 提取、取色及结果复制 | 54.35 | 51.21 |
| 几何比较及结果行生成 | 0.27 | 0.30 |
| 重复设置/离屏绘制两个已有视图 | 33.41 | 12.65 |
| 重读标准 + 待测图 + 整个窗口离屏渲染 | 175.09 | 165.46 |

重复刷新改善约 62%，整对图像重读流程改善约 5.5%。结果行生成原本不足 1 ms，并非主要瓶颈；单图计算仍有读图和 OpenCV 运算开销，不能把刷新提升当作全流程同比提升。这里未声称达到某个生产节拍。

原始报告为 `verification/performance-before-Release.json`、`performance-after-Release.json`，Debug 对应 `*-Debug.json`。Debug 使用 `/Od`、`/MDd`、Debug OpenCV，保留本机单步和检查，速度明显慢于 Release；日常检测和速度评估使用 Release。

Debug 同条件中位数：单图提取/取色 **1047.64 → 495.03 ms**（约减少 53%），重复视图刷新 **41.90 → 14.46 ms**，标准/待测整对重读及渲染 **1613.50 → 820.38 ms**（约减少 49%）。Debug 和 Release 的热点占比不同，因此收益不能互相套用。

在项目目录复测：

```powershell
.\build.ps1 -Configuration Release -NoPublish
.\build\verification\Release\Verification.exe .. --benchmark manual
.\verify.ps1 -Configuration Release
```

`RefreshExistingViews` 是同一个已加载分析反复设置到两个视图再离屏绘制；`LoadPairAndRender` 是实际调用窗口 `LoadPairAsync` 后离屏绘制，不是屏幕端到端延迟。图库 CSV 对照基线使用 `verification/performance-baseline/` 中的原始文件。

## 导出使用

- 点击 **导出报告**：默认 `.html`；双击后浏览器可离线查看。图片已嵌入文件，复制 HTML 不需要附带原图。
- 顶部按图像统计 OK、NG、待确认、仅量化、错误；图像下方显示点位、ΔE00 与阈值条、逐点结论和超限原因。
- 匹配不确定只展示候选，不标成确认缺失，也不据候选色差判 OK；通道差阈值超限会单独说明。
- 数值明细默认折叠；标准图路径、哈希等追溯数据也在明细里。色块来自采集 RGB，不模拟人工 Lab 微调后的真实印刷颜色。
- **批量检测** 同样可导出 HTML，每张图折叠展示；取消后写明已处理数量，未处理图没有结论。打印前先展开所需图像。
- 保存对话框切换 **详细测量数据（CSV）**，仍可得到原来的全部字段，用于二次计算；本次没有改变 CSV 列顺序与数值格式。

样例：`verification/visual-report.html`、`visual-batch-report.html`、`visual-missing-report.html`。后两个含测试构造的缺点、错误/取消等情形。

## 验证与使用限制

回归包含已有图库、上下位移、缺点、多点、歧义、标准往返及 WPF 离屏渲染；新增检查覆盖原生 BGR 步长/像素、句柄释放后的冻结位图可用性、缓存复用、报告状态/超限原因/转义与取消后的完整 HTML。

本次 Debug/Release 各通过 99 张图像、231 个 mark 的回归。优化后 `gallery-comparisons.csv` 与基线逐字节一致，SHA-256 为 `7E3BC3DBBA094025A7FC733D350877CACD3221FF2B7158CE4ED8ED8ACD990BDB`。这覆盖已有数据的数值与判定一致性，不代表任意新图的生产准确率。

自动浏览器受到本地文件 URL 安全策略限制，本次没有绕过策略进行浏览器外观验收；报告已做内容与结构验证，浏览器实际排版仍需在本地打开样例查看。

当前正在运行的旧 Debug 窗口占用常规输出目录，所以 Debug 在 `build/performance-debug/` 独立目录编译/验证。Release 的 `publish/` 已更新；关闭旧 Debug 窗口后，在 VS 重新生成即可更新常规 F5 输出。不要只复制新版 C# 程序集：新增预览/计时入口要求使用配套 Native DLL，工程自动复制已覆盖此依赖。
