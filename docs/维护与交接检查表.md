# 维护与交接检查表

## 当前维护入口

先读 [项目全局导航与开发指南](项目全局导航与开发指南.md)，再按“修改目的 → 文件 → 方法 → 验证”定位。格式与注释规则见 [代码规范](代码规范.md)。

## 每次改动前

- 查看 Git 状态，保留已有修改；源码整理、算法改动、环境变更分别说明。
- 确认使用 F5 输出还是 publish，记录 Debug/Release 和 ABI 版本。
- 确认问题来自提取、配准、测量资格、颜色阈值、展示还是报告，避免在显示层修补业务判定。
- 数据对照使用同一图像与参数；文件夹名不能代替逐点真值。

## 最容易改错的边界

| 边界 | 必须保持的关系 |
|---|---|
| 编号 | 标准 Id ≠ 标准列表下标 ≠ 待测 ObservedIndex |
| 坐标 | ROI 归一化、算法原图 px、WPF DIP 分开；显示倍率不影响测色 |
| 数值 | 浮点 Lab 不使用 Lab8 偏置；ΔL/a/b 为待测减标准 |
| 统计 | 像素 σ ≠ 跨拍摄 σ；人工目标 ≠ 原始采样均值 |
| 质量 | 配准可靠后再评估测量资格；无法测量不能变成产品颜色 NG 或 OK |
| 结果 | UI/CSV/HTML 消费同一强类型结论，不按显示文字重新推导 |
| 所有权 | 原生句柄唯一释放；借用像素在释放前完成复制；位图跨线程前 Freeze |
| 提交 | 设置/建标先准备独立草稿，全部成功才替换当前状态 |
| 取消 | 不能中断正在执行的同步 Native 调用；按图边界取消并排空已完成结果 |
| 持久化 | 标准相对路径相对 JSON 解析；读取不能隐式重新学习目标 |
| 复制 | 新增可变模型属性时核对 Copy 是否仍真正隔离草稿 |
| 参数 | 新增提取参数同步修改 ToNative/SameExtraction、Native ABI、设置输入及测试 |
| 发布 | Native DLL/PDB/OpenCV 配置配套；运行旧 publish 不代表运行最新源码 |

## 按改动选择验证

| 改动 | 至少执行 |
|---|---|
| 注释、空白 | 格式检查；语言解析或构建；核对非注释 token 和 XML 实际结构 |
| 提取/取色 | 原生测试、弱对比和不同尺寸实拍数据、质量资格 |
| 匹配 | 位移双向、旋转、比例、重排、真实缺失和歧义 |
| 颜色因子/阈值 | 数学参考、ColorFactorTests、标准往返及报告 |
| 标准/设置 | 多图均值、失败恢复、取消保持、人工偏移、ClearStandardTests |
| 预览/交互 | ViewportInteractionTests、离屏布局和相关实际操作 |
| 报告/批量 | ReportTests、UpgradeTests，检查写入失败与取消后的文件 |
| 工程/部署 | 对应配置构建、DLL/PDB 核查、包内依赖/许可/文档及自检 |

不要为纯注释改动宣称性能提升。不要将离屏渲染称为人工界面验收，也不要将参考图自比通过称为测色准确度验证。

## 交接验收

- 同事能从根目录脚本准备环境、编译和启动 WPF。
- 能在 Native 中命中断点，确认实际加载 DLL/PDB。
- 能沿单图、建标、设置及报告链找到业务决策位置。
- 知道标准 JSON、示例图、真实图库、便携包分别存在哪里。
- 能区分已实现的相对 Lab 检测与尚未实现的标准板校准方案。
- 能独立运行所改模块的验证并找到结果；无法执行的检查注明原因。
