# 代码规范与维护约定

## 职责和文件组织

2026-10-16 全项目整理后的文件导航、注释口径与职责拆分见 [全项目代码整理说明](全项目代码整理说明.md)。

- `mark_color.cpp` 只负责 C ABI 接口、参数指针检查、结果句柄生命周期和异常边界。
- `mark_detection.cpp` 负责图像读取、分割、轮廓筛选、内圈取色和统计。
- `mark_matching.cpp` 负责几何配准、代价矩阵、一对一分配、歧义与比较结果。
- `mark_candidates.cpp` 负责多尺度候选；`mark_quality.cpp` 负责原分辨率精修和原始质量证据，不重复实现 C# 的业务阈值判断。
- `color_difference.cpp` 负责 CIEDE2000 数学；公式分支必须保留已有数值回归。
- `mark_color_internal.h` 是 Native 内部约定；对外结构体仍只放在 `include/mark_color.h`。
- C# 的参数、标准、结果模型在 `Models/` 下按类分文件。`Native.cs` 集中保留互操作结构体与 P/Invoke，便于和 C++ 头文件核对。
- WPF 事件处理负责操作编排，业务判定放在 `Inspection`，画面标注使用该判定结果。不要在绘图中重新决定 OK/NG。
- `MainWindow.Settings.cs` 负责设置提交，`MainWindow.Reports.cs` 负责导出操作，`MainWindow.Workflow.cs` 负责建标与恢复；窗口公共状态仍在同一分部类中管理。
- `ImageViewport.cs` 负责视图变换与交互，`ImageViewport.Rendering.cs` 负责绘制；不得从绘制方法触发检测。

## 命名和代码布局

- C++ 内部类型使用 PascalCase，函数/变量使用 camelCase，常量使用 `k` 前缀；公开 `mc_*` ABI 名称保持稳定。
- C# 类型/公开成员使用 PascalCase，局部变量/私有字段使用 camelCase；XAML 事件处理保留现有 `*_Click` 命名。
- 多步骤函数一行只写一个语句，控制分支使用大括号，函数之间留空行。
- C++ 使用四空格缩进、Allman 大括号、120 列换行。C# 使用四空格和 Allman；简单自动属性、短表达式成员可写一行。
- C++ 所有命名空间也逐层缩进四空格（`NamespaceIndentation: All`）；匿名命名空间注明用途。`mark_matching.cpp` 中模块、匿名空间、函数依次形成清楚的层级。
- 长对象初始化、参数列表和布尔条件按职责/逻辑项换行；不要用多层三元表达式压缩业务流程。
- 常见数学符号 x/y、L/a/b、u/v 可以保留，但必须解释单位或公式含义。一般逻辑优先使用 `referenceIndex`、`observedIndex`、`sampleMask` 等具体名称。
- 配准的缩放旋转分量使用 `scaledCosine`、`scaledSine`，平移使用 `translateX/Y`；注释说明原图/局部坐标、单位、下标方向及哨兵意义。公式中有通行定义的 C、h、G、RT 等保留原符号并解释计算阶段。
- 注释说明约束、意图、单位和边界，避免逐行复述赋值。采样统计口径、色相角跨越分支、Hungarian 哨兵下标等应明确说明。

## 算法与互操作约束

- 点、轮廓、半径都使用原图像素。显示缩放与图像配准不改变取色像素。
- 几何匹配不使用颜色决定对应关系；缺墨造成颜色大幅变化时仍应比较同一个点。
- 配准不确定不能显示为确认缺失，也不能因为暂选对应的色差小就判 OK。
- Native 内部通过 RAII 管理资源；仅在成功时释放 unique_ptr 所有权给 C API 句柄，C# 用 SafeHandle 释放。
- 公开结构体字段顺序、类型、Pack=8、cdecl、ABI 版本必须两端同步。内部模块拆分不改变公开数据布局。
- 改变数值算法时说明预期行为变化，并运行针对性测试及图库回归；纯整理应对照既有报告检查测量和判定一致性。
- 色差因子属于 `ColorDifferenceSettings`，不混入几何容差；标准保存、检测、跨采样偏差与报告使用同一参数。`MainWindow.Presentation.cs` 管理展示层级，设置提交由 `ApplySettingsAsync` 负责，成功后才替换界面状态。

## 配置和生成文件

`MarkColorNative.vcxproj` 显式包含本工程的编译/链接配置。OpenCV 路径和版本由可见的 `OpenCV.props` 提供一处共用来源，C++ 编译、WPF 复制和测试不各自保存一套 SDK 路径。

不要手工修改 `build/`、`bin/`、`obj/` 的生成代码。旧 `build/native/*.slnx` 属于独立 CMake 输出；新增 Native 源文件时同时更新 `.vcxproj`、`.filters` 和 `CMakeLists.txt`。

## 格式化与检查

项目根目录包含 `.clang-format` 和 `.editorconfig`，可供 VS 和命令行共用。在 MarkColorDemo 目录执行：

```powershell
.\format.ps1          # 整理 C++、C#、XAML/工程 XML 与 PowerShell
.\format.ps1 -Check   # 只检查，检测到格式差异时返回失败
```

脚本使用 Path 中的 clang-format，或 Visual Studio 自带的 x64 clang-format。C# 由 `build-support/SourceFormatter` 使用 .NET SDK 自带 Roslyn 语法树整理，不下载第三方格式包：补齐控制分支大括号、修正参数续行缩进、在成员之间留空行，并检查非大括号 token 未改变。修改格式工具本身后，也应再次运行 `-Check` 确保幂等。

`build-support/format-xml.ps1` 校验并整理 XAML、工程和属性文件，使用两空格缩进和逐行属性；`format-scripts.ps1` 按 PowerShell 语法 token 整理脚本缩进，保留字符串/Here-String 内容，并在改写后复核语法和 token。PowerShell 使用 UTF-8 BOM，兼容 Windows PowerShell 5.1 中的中文。

范围为本项目的 `src/`、`native/`、`tests/`、`build-support/` 和根目录构建脚本；不改 OpenCV、SDK、`bin/obj/build/publish/dist` 等第三方或生成内容。CMake 源文件列表按文件逐行维护。

格式检查不能代替命名和结构审查。比如，单行写完复杂对象初始化即使通过工具检查，也应人工展开。

验证开发改动：

```powershell
.\build.ps1 -Configuration Debug -NoPublish
.\verify.ps1 -Configuration Debug
.\build-support\check-symbols.ps1
.\build.ps1 -Configuration Release
.\verify.ps1 -Configuration Release
```
